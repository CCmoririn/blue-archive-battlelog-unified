# 防衛メーカーの仕様と検証

防衛メーカーは、選択シーズンに記録された有効な防衛6人編成から候補を選びます。STRIKERの配置とSP2人の組み合わせを保持し、特定のSPを強制採用しません。一般版と限定版は同じ計算処理を使い、それぞれのデータだけで評価します。

## 攻撃条件

複数の生徒を指定すると、その条件に合う攻撃を対象にします。1人だけならその生徒を含む攻撃、未指定ならシーズン全体の攻撃が対象です。空欄の枠は条件にしません。

「配置まで完全一致」はSTRIKERの指定枠に適用します。SPは左右を入れ替えても同じ条件です。複数条件は等しく重み付けし、各条件内では異なる攻撃6人編成を等しく扱います。同じ条件の重複指定では重みを増やしません。いずれかの条件に一致する有効なログがない場合は、全条件を合わせた推薦を出しません。

## 推定と順位

`battlelog_defense.py` で、生徒と枠、STRIKERの射程・遮蔽、SPペア、完成編成、攻撃側と防衛側の生徒などの組み合わせを使い、防衛結果を推定します。既存のNumPyを使ったL2正則化ロジスティック回帰で、正則化係数は128です。クラス比を人為的に50%へ揃える処理はしていません。

推定対象の攻撃群と重みは、すべての防衛候補で共通です。総合評価には次の式を使います。

`総合評価 = 100 × (全体の推定値 × 0.75 + 苦手側の推定値 × 0.25)`

苦手側の推定値は、推定が低い攻撃から重みの合計20%分を集めた平均です。境界の攻撃は必要な重みだけ含めます。この配分は、平均の高さに加えて苦手相手への弱さを考慮するための設計値です。総合評価の点数を勝率とは扱いません。

20試合未満、または勝敗が片方しかないデータでは、学習した生徒効果を使わず、シーズン全体の勝敗を補正した参考値を使います。空の勝敗、生徒の欠損・未登録、種別の不整合、同一編成内の生徒重複、攻防の勝敗矛盾を除外します。同一試合と確認できる重複も除きます。元のシートは変更しません。

学習結果はデータ・シーズン・公開範囲・マスターに対応するキーでプロセス内に保存します。初回とデータ変更後に計算し、同じデータへの検索では再利用します。一般版と限定版の保存キーを分けています。

## 実績と推定の見方

「参考」は、候補6人の実績が5試合未満、または評価する攻撃のうち同一対戦の実績がある範囲が半分未満の候補です。実績がある範囲でも、表示する評価値はモデルの推定です。実績のない対戦を30%などの固定値にはしません。

限定版の詳細欄には、攻撃条件ごとの試合数・勝数・実績の防衛勝率、推定値、苦手な攻撃、全候補の比較を表示します。検索時の結果をそのまま展開するため、入力欄の未送信の編集は詳細に反映しません。プレイヤー名やログIDは評価結果に含めません。

## オフライン検証

2026年11月2日に一般用シートから保存したs10・s11のデータを使用しました。マスターとの照合や不整合の除外後、有効行はs10が3,681試合、s11が753試合です。これは取得時点のデータで、現在の本番全件ではありません。限定版固有のログでの予測性能は未検証です。

登録日の境界で、約60%を学習、約20%を設定選択、残りを確認に使いました。3種類のモデル設定を設定選択用の期間で比較した後、選んだ設定を確認期間へ適用しました。マスターは保存時点のもので、各対戦当時の状態を復元したものではありません。

| 確認期間 | 試合数 | 6人実績を補正した集計のLog loss | 採用モデルのLog loss | 集計のBrier score | 採用モデルのBrier score |
| --- | ---: | ---: | ---: | ---: | ---: |
| s10・2026年3月29日以降 | 748 | 0.6780 | 0.6540 | 0.2424 | 0.2312 |
| s11・2026年9月28日以降 | 151 | 0.5008 | 0.5068 | 0.1505 | 0.1514 |

両指標は小さいほど予測誤差が小さいことを示します。s10では比較した集計より誤差が減りました。s11では集計を上回っておらず、予測精度の改善は確認できていません。これらの指標だけで推定確率の妥当性が確定するわけではありません。[確率予測の評価に関する説明](https://scikit-learn.org/stable/modules/calibration.html)

検証は投稿された対戦についての予測確認です。記録されていない組み合わせの結果や、全候補の真の順位を証明するものではありません。育成差、実際に遭遇する攻撃の比率、投稿の偏りも解消していません。ログの日付は登録日であり、実際の対戦日と同じとは限りません。

保存データでの未指定検索では、s10・s11とも上位5件すべてが有効な実在編成で、生徒の重複はありませんでした。どちらも上位5件に水着シロコを含まない結果でしたが、水着シロコを含む編成を候補から除く処理はありません。

再実行には、保存データのフォルダーを指定します。ツールは外部通信と元データへの書き込みを行いません。

```text
python -B tools/validate_defense.py --snapshot SNAPSHOT_DIRECTORY --output REPORT.json
python -B -m unittest discover -s tests -v
node tests/test_frontend.js
node tests/test_admin_frontend.js
```

Windowsのサンドボックスで一時ファイルの置き換えが拒否される場合は、`TEMP` と `TMP` を作業フォルダー内の専用ディレクトリに設定してテストします。
