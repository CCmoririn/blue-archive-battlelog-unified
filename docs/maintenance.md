# 保守・検証・復旧の手順

この文書は、2026年11月2日の改修内容と運用上の前提を記録したものです。本番のGoogleシート、GAS、Render設定を自動で変更するものではありません。

## 変更した処理

- アップロード画像は元の名前を使わず、画像のヘッダーから形式を判定して、一意な名前で保存します。ファイルの内容は変えません。リクエストの上限は既定で32MBです。
- OCRの呼び出し元に、スレッドとプロセスをまたぐロックを置きました。画像前処理・座標・認識回数・文字の解析方法は変更していません。
- 確認画面の送信には一度発行したトークンを使います。同じ確認画面を再送しても、完了済みならシートへ再登録しません。
- 登録処理の状態をSQLiteに記録します。シート書き込み・GASの結果が不明な場合、自動では繰り返しません。キャッシュ更新だけが失敗した場合は、同じ確認画面の再送でその段階から再開できます。
- 一般版の変換後行は、最新行の位置ではなく登録時のIDで探します。IDが重複している場合や見つからない場合は、別の行を採用せずに処理を止めます。
- JSONは一時ファイルを書き終えてから置き換え、直前の正常なファイルを `.bak` として残します。破損していた場合は `.bak` を利用します。両方を読めない場合は、無断で全件再生成しません。
- キャッシュへの追記はIDなどの一致する行を置き換えます。再送や初回再生成で同じ行が二重に増えるのを防ぎます。
- 投票は対象シーズンを必須とし、シート側の件数を基準に更新します。保存に成功してから画面とCookieを更新します。
- 投票のCookieもシーズン別の名前に変えています。保存済みの票数は変えませんが、旧Cookieの投票済み表示は引き継ぎません。
- 射程・遮蔽検索では、生徒マスタの索引を検索ごとに一度作ります。STRIKERの位置一致、SPECIALの順不同一致、名前の正規化は維持しています。
- Googleとの通信をimport時に実行せず、マスタは必要になった時点で取得します。シート通信とGASの通信には待ち時間の上限を設けています。
- 未使用の限定版は既定で読み込みません。有効にする場合は認証を必須にします。

画像の受付制限については [Flaskの公式説明](https://flask.palletsprojects.com/en/stable/patterns/fileuploads/) も参照してください。

## 保存先と本番の前提

`BATTLELOG_DATA_DIR` が未指定の場合、従来と同じく起動時のカレントディレクトリを使います。指定した場合は、その下に次のデータを置きます。

| 保存先 | 内容 |
| --- | --- |
| `cache_general/`、`cache_limited/` | 検索用JSONと直前の正常なJSON |
| `uploads/` | 画像。OCRへは保存時と同じバイト列を渡す |
| `.battlelog_runtime/submissions.sqlite3` | 確認トークンと登録処理の進行状況 |
| `.battlelog_runtime/locks/` | プロセス間のロック |
| `.battlelog_runtime/cache_snapshots/` | 保守ツールで全件更新する前の退避 |

これらはGitでは管理しません。設定ファイル・認証情報も引き続き管理対象外です。

Renderの通常のファイルシステムは一時的なもので、再起動・再デプロイで変更が失われます。処理記録やキャッシュだけに保存した行を再起動後も残すには、永続ディスク上の保存先を指定する必要があります。[Renderの公式説明](https://render.com/docs/disks)

**このロックが調整できるのは、同じデータ保存先を共有するプロセスです。** 本構成は1インスタンスでの運用を前提にします。別々のディスクを持つ複数インスタンスや、人・別スクリプトによるシートの同時編集まで調整するものではありません。複数インスタンスにする場合は、GAS側のロックや外部DBなどを含めて設計する必要があります。

## 起動設定

リポジトリ直下からの起動先は `manage:application` です。追加したルートのProcfileでは、1ワーカー・4スレッド・タイムアウト180秒としています。既存のRenderが別の起動コマンドを使っている場合、Procfileの追加だけでは設定は変わりません。

既存の一般版サブフォルダから `app:app` を起動する方法も維持しています。`/healthz` はGoogleへ接続せずに応答します。外部サービスやデータ全体の正常性を保証するヘルスチェックではありません。

| 追加設定 | 既定値・用途 |
| --- | --- |
| `BATTLELOG_DATA_DIR` | 未指定なら起動ディレクトリ。永続ディスクを使う場合はその絶対パス |
| `BATTLELOG_MAX_UPLOAD_MB` | `32`。画像を含むリクエストの上限 |
| `ENABLE_LIMITED_APP` | `0`。`1` にした場合だけ限定版を読み込む |
| `LIMITED_ACCESS_TOKEN` | 限定版を有効にするときは必須。十分長いランダムな値を設定する |
| `GENERAL_TRANSFER_SHEET_NAME` | `一般版から転送`。`一般版から転送_{season}` のような指定も可能 |

限定版は、ブラウザではHTTP Basic認証のパスワードにトークンを入力して利用します。APIでは `Authorization: Bearer ...` も利用できます。本番ではHTTPSを使ってください。トークンをURLやリポジトリへ記載しないでください。

`GENERAL_TRANSFER_SHEET_NAME` を変える場合は、実シートとGASの転送先を先に確認します。転送行に `season` または `シーズン` 列がある場合は、その値で対象を絞ります。列のない旧形式については、Pythonだけでシーズンを判断できないため、従来の読込方法を維持しています。`source="限定"` という既存ラベルも、実際のデータの機密性を示すものと決めつけて変更していません。

## 読み取り用の確認コマンド

リポジトリ直下で実行します。`cache-check` はシートへ接続せず、JSONがない場合も再生成しません。`submissions` は処理記録を読むだけです。出力には処理トークンが含まれるため、公開しないでください。

```text
python -B tools/maintenance.py cache-check --season s11
python -B tools/maintenance.py submissions
```

JSONの全件更新は定期実行にしていません。実シートを確認したうえで、明示的に実行します。このコマンドはシートを読み取り、ローカルJSONを更新します。既存JSONは更新前に退避します。

```text
python -B tools/maintenance.py cache-refresh --season s11 --apply
```

新しい限定API経由でキャッシュだけに加えた行には `_cache_only` を付け、再生成時も残します。旧コードで作られたキャッシュにはこの印がないため、過去のキャッシュだけに存在する行を完全には判別できません。全件更新前の退避を保管してください。シート上の修正・削除は、JSONの全件更新を行うまで検索に残る場合があります。

## 登録途中で止まった場合

処理記録の状態には、次の意味があります。

| 状態 | 対応 |
| --- | --- |
| `prepared` | 確認画面を表示した段階 |
| `inserting`、`converting`、`uncertain` | 書き込み結果が不明な可能性がある。元シートと出力シートを確認し、同じ内容を新たに投稿しない |
| `inserted` | 変換前シートへの登録済み。処理再開時は追加登録せず変換へ進む |
| `converted` | 変換を呼び出した後。確認画面の同じ内容を再送すると、ID確認とキャッシュ更新から再開する |
| `complete` | 完了。同じ確認トークンを再送してもシートには追加しない |

通信が切れた直後は、相手側で処理が完了している場合があります。GAS本体をまだ確認していないため、すべての外部処理の成功・失敗を完全に判定することはできません。結果不明の処理を自動再試行しないのは、重複を避けるためです。

投票も、シート更新後に通信が切れたりローカル保存に失敗したりした場合、結果が不明になることがあります。この場合は画面に再読み込みの案内を表示します。既存の投票はCookieを使う簡易方式であり、本人確認や不正な多重投票を完全に防ぐ仕組みではありません。

## 検証

テストは外部通信を遮断し、一時データとシートの代用品を使います。本番の認証情報は不要です。OCRは実行せず、呼び出し部分だけを代用品に置き換えます。

```text
python -B -m unittest discover -s tests -v
node tests/test_frontend.js
```

Windowsの制限付き実行環境で一時フォルダ内のファイル置き換えが拒否される場合は、書き込み可能な専用フォルダを作り、`BATTLELOG_TEST_TMP` にその絶対パスを指定します。本番用のキャッシュをテスト先に指定しないでください。

GitHub ActionsにもWindows・Linux用の同じテストを追加しています。ローカルでの実行結果と、GitHub上での実行結果は別です。

## 改修前へ戻す場合

改修前のコミットは `40577727bd88c5ae7d20f59c1d018700be19f075` です。今回の改修は別ブランチで行い、元の `master` は変更していません。

ローカルのコードを戻す場合は、未保存の変更がないことを `git status` で確認してから `git switch master` を実行します。変更がある場合は先に保存し、`reset --hard` や `clean` で消さないでください。

本番のコードを戻す場合は、元のコミットを再デプロイし、起動設定・保存先の設定も元の構成と整合させます。旧版は `BATTLELOG_DATA_DIR` を参照しないため、コードだけ戻しても同じ場所のキャッシュを使うとは限りません。

**コードを戻しても、シートへ書き込んだデータや投票数は元に戻りません。** ロールバックを理由に古いシートやローカルキャッシュを本番へ上書きしないでください。シートの復旧は、対象の変更とバックアップを確認して別途行います。

今回、変更前のローカルファイル一式と、Git履歴の完全なbundleを別フォルダへ退避しています。退避には認証情報が含まれるため、アップロードや共有はしないでください。これは本番の最新シート・キャッシュ・Render設定を保存したものではありません。
