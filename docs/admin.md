# 管理画面の使い方

管理画面は `/admin/` から開きます。管理用パスワードでログインしてください。公開サイトには管理用のリンクを表示しません。

## キャラを追加・編集する

「キャラ管理」でキャラ名、種類、画像URLを入力します。STRIKERでは射程と遮蔽も選択してください。画像URLは `https://` で始まるものを使い、プレビューで表示を確認します。

保存すると、既存のキャラマスタと名前補正用の辞書に反映し、サイトのキャラ一覧も更新します。反映だけをやり直す場合は「サイトへ今すぐ反映」を押してください。OCRの処理方法は変更しません。

登録済みのキャラは一覧の「編集」から画像・射程・遮蔽を変更できます。名前と種類は戦績との照合に使うため、この画面では変更できません。既存の属性や地形適性など、編集対象以外の列は残します。新規追加時にその情報も必要な場合は、元シートで入力してください。

編集前の情報は「変更履歴」に残ります。「この編集前に戻す」で画像・射程・遮蔽を戻せます。その後に別の編集がある場合は上書きを止めます。新規追加したキャラの削除は行いません。

## シーズン切り替えを予約する

1. 「シーズン管理」で、次シーズン名を `s12` のように入力して準備します。
2. 「準備チェック」で、入力・出力・転送・辞書を確認します。
3. 準備済みのシーズンと切り替え日時を選び、予約を保存します。日時は日本時間です。
4. 予約内容が画面に表示されたことを確認します。

シートの見出しをひな形として使い、過去の戦績はコピーしません。準備が途中で止まった場合は、同じシーズン名で再開できます。同名のシートが別の構成で存在する場合は上書きせずに止めます。シート間転送の反映に時間がかかる場合は、少し待ってから再チェックしてください。

切り替え時刻以降は、投稿先と検索の初期選択が新シーズンになります。過去のシーズンも検索できます。予約情報からアクセス時に判定するため、Renderが休止していても次のアクセス時には正しいシーズンを使います。

切り替え前に開いたアップロード・確認画面は、表示されている投稿先を維持します。画像のシーズンと投稿先を確認してください。

予約日時を変更する場合は、同じ画面で予約を保存し直します。切り替え前なら「予約を解除」で取り消せます。適用後に戻す場合は「現行シーズンを変更・元へ戻す」を使います。この操作では戦績データは変更せず、日時予約を解除します。

## 状態と履歴を確認する

「状態確認」では、キャラの画像URL・射程の不足と、登録処理の確認候補を表示します。画像のリンク切れまでは自動判定しないため、プレビューでも確認してください。

投稿の確認候補には、まだ処理中のものも含まれる場合があります。結果不明の投稿は、元シートと出力シートを確認します。管理画面から自動で再登録することはありません。

「変更履歴」には最近40件を表示します。保存開始後にエラーが出た場合は、履歴と元シートを確認してから再操作してください。履歴自体はシートに追記して残しています。

## 設置・復旧時の設定

管理機能は既存の非公開シート内の `_battlelog_admin` タブへ、設定と変更履歴を保存します。このタブの行を並べ替えたり、途中の記録を書き換えたりしないでください。

| 環境変数 | 用途 |
| --- | --- |
| `BATTLELOG_ADMIN_SHEET_ID` | 非公開の管理設定保存先。通常は既存の入力用シート |
| `BATTLELOG_ADMIN_PASSWORD_HASH` | 管理用パスワードのハッシュ |
| `BATTLELOG_ADMIN_SESSION_KEY` | ログイン情報の署名用キー |

初期設定タブの作成は `python -B tools/admin_setup.py --apply` で行います。設定済みのタブは初期化し直しません。初期パスワードを作る場合は `tools/admin_credentials.py --output <リポジトリ外の専用フォルダ>` を使います。既存の認証ファイルは上書きしません。生成したファイルを公開・共有しないでください。

ログインの有効期間は12時間です。パスワード設定のハッシュを変更すると既存のログインも無効になります。ログイン試行回数に制限を設け、更新操作にはフォームごとの確認用トークンを使っています。

この構成は1インスタンス用です。Googleへ接続できない場合は最後に取得した予約情報を使います。再デプロイ直後などで有効な設定が一度も取得できていない場合は、誤ったシーズンへ投稿しないよう処理を止めます。

管理機能を導入する前のコードへ戻す際は、そのコードがシーズン予約を読まないことに注意してください。すでにシーズンを切り替えた後なら、旧コードの現行シーズン設定も実際の運用と合わせる必要があります。コードのロールバックではシートへの変更は戻りません。
